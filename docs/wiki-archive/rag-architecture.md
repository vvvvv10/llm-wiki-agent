# RAG 检索增强生成

## 什么是 RAG，它解决什么问题
RAG（Retrieval-Augmented Generation，检索增强生成）是先从外部知识库检索与问题相关的文档片段，再把它们作为上下文交给大模型生成答案的架构。它解决三个问题：模型知识过时或缺失、私有/企业数据不在训练语料中，以及生成内容无依据的幻觉。相比微调，RAG 更新知识只需重建索引，且可溯源、可引用、成本低。

## 文档切分
切分（Chunking）把长文档分成 200~800 Token 的片段：按标题层级、段落等语义边界切，保留少量重叠（overlap）避免语义断裂；每块附带文档标题、路径、章节层级等元数据用于引用；过小块召回噪声大，过大块稀释相关性。

## 召回
召回阶段用 BM25 关键词检索与向量语义检索取回 Top-N（如 20~50）候选。BM25 擅长精确词与术语匹配，向量擅长同义改写；二者混合（Hybrid）通常取长补短，再做去重与元数据过滤（时间、来源、权限）。

## 重排
重排（Rerank）用交叉编码器或重排模型对 Top-N 候选与问题逐对打分，把最相关的前 3~8 条送入生成，成本低但显著提升精度；也可用 LLM 按相关性打分过滤。

## 证据约束与引用
证据约束要求模型“仅依据提供的片段作答，不补充未出现的信息”，并在 Prompt 中明确片段编号。引用策略：答案后标注 [1][2] 对应片段 ID，展示原文出处；片段不足或与问题无关时触发拒答（“知识库中未找到”），而不是编造，从而提升忠实度与可信度。
