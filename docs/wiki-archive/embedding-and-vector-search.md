# Embedding 与向量检索

## 向量化原理
Embedding 是把文本映射为固定维度的稠密浮点向量（如 768/1024/1536 维），由编码器在大规模语料上训练得到，语义相近的文本在空间中距离更近。索引时对每个文档块向量化入库，查询时把问题同样向量化，实现跨语言、改写式的语义匹配。因此 Embedding 是向量检索的前提：没有向量化就无法做向量检索，二者关系是“表示”与“查找”。

## 相似度度量
- 余弦相似度：只看方向，值域 [-1,1]，最常用。
- 点积：归一化后等价余弦，计算快。
- 欧氏距离（L2）：绝对距离，需与建库度量一致。度量不匹配会导致召回严重下降，建库与查询必须使用同一模型与同一度量。

## HNSW 与 IVF 索引
精确最近邻是 O(N) 暴力扫描，大规模需近似最近邻（ANN）：
- HNSW：多层跳表图导航，召回高、延迟低，内存开销大，参数 M、efConstruction、efSearch 权衡精度与速度。
- IVF：聚类分桶，查询只扫 nprobe 个最近簇，内存省、训练耗时，适合超大规模。
另有 PQ 量化压缩向量，减小内存。

## 与 BM25 的对比
BM25 基于词频的词面统计检索，可解释、无需训练、对专有名词与精确匹配好，但不懂同义与改写；Embedding 向量检索理解语义，但对稀有词、型号数字敏感且需维护模型。两者互补。

## 混合检索
混合检索把 BM25 与向量两路召回结果合并，用 RRF（倒数排名融合）或加权分数归一化，再送重排模型。工程上先并行两路，取并集去重后重排，兼顾词面命中与语义泛化。
