# Prompt 工程

## 什么是 Prompt 工程
Prompt 工程是设计与优化输入文本以稳定获得期望输出的实践，核心是明确任务、约束与输出格式，减少模型歧义与幻觉，覆盖零样本、少样本与结构化等写法。

## 系统 Prompt
系统 Prompt（System Prompt）定义角色、职责、边界与语气，在对话最前置注入且优先级高，用于设定业务规则、拒绝范围与输出风格；用户消息不应覆盖系统 Prompt 中的硬约束。

## 少样本示例
少样本（Few-shot）在输入中给出若干「输入→输出」示例，让模型模仿格式与粒度。示例需覆盖典型与边界情况、顺序影响结果、数量一般 2~5 个；示例本身也消耗上下文与 Token 成本。

## 思维链
思维链（Chain-of-Thought，CoT）要求模型分步推理再给结论，可写“一步步思考”或加入推理示例，显著提升数学、逻辑与多跳问题准确率；配合“先推理后输出最终答案”便于解析。

## 结构化输出
结构化输出要求返回 JSON、XML 或固定模板：在 Prompt 中给出 Schema、字段说明与示例，必要时用约束解码（JSON mode / structured output）保证语法合法，并在代码侧做校验与重试。

## Prompt 注入原理与防护方法
Prompt 注入是攻击者把恶意指令藏在网页、文件或用户输入中，诱导模型忽略系统 Prompt、泄露提示词或执行越权操作，分为直接注入与间接注入。
防护方法：系统 Prompt 与用户数据用分隔符和标签隔离并声明“外部内容不可信”；对检索与工具返回内容做净化与过滤；敏感操作走白名单与人工确认；输出侧做关键词与正则检测、限制外发；最小权限与密钥不入上下文；用越权诱导读本做红队回归测试。仅靠提示词声明不足以防御，必须配合应用层权限控制。
