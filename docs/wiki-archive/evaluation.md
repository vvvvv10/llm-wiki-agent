# 大模型评估

## 为什么需要评估
大模型输出具有随机性，改动 Prompt、模型版本或检索参数都可能影响质量与成本，评估为调优、选型与上线决策提供依据。如何评估大语言模型，通常结合人工评估、自动指标与模型评判三条路径。

## 人工评估
人工评估（Human Eval）让标注者按维度打分：准确性、完整性、相关性、格式与语气。做法是制定清晰评分标准（rubric）与分级示例，多人交叉标注并计算 Kappa 等一致性系数，成本高但最接近真实体验，常用于建立基准集。

## 自动评估指标
- 文本生成：BLEU、ROUGE、BERTScore 比对参考答案，语义重合度高分高。
- 分类/抽取：准确率、精确率、F1。
- 检索：Recall@K 表示前 K 条召回中包含正确文档的比例，是 RAG 的核心前置指标；另有 MRR、NDCG。
- 答案正确性：字段抽取后与标准答案做精确或归一化匹配。

## LLM-as-a-judge
用强模型按评分标准对输出打分或两两比较（胜率），可要求输出 JSON 分数与理由，成本远低于人工、可规模化。需注意位置偏差（交换 A/B 顺序）、自我偏好与分数漂移，建议先用少量人工标注校准模型评判的一致性。

## 忠实度与幻觉
忠实度衡量答案是否被检索证据支撑：可统计被证据蕴含的句子比例（faithfulness），幻觉率则统计无依据陈述占比；RAG 场景还应检查引用是否指向真实命中的片段。

## A/B 与回归测试集
维护固定不变的回归测试集（含典型、边界、拒答与对抗样例），每次改动后全量跑分并与基线对比，防止指标回退；线上用 A/B 实验按真实用户指标（采纳率、点踩率、人工转接率）验证，同时监控延迟与成本。
