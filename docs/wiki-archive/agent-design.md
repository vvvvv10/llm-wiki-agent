# Agent 设计

## Agent 是什么
Agent 是以大模型为决策核心、通过“规划→行动→观察”循环自主完成多步任务的系统，与单轮问答的区别在于它能调用外部工具、维护状态并根据反馈调整计划。

## 规划与任务分解
规划（Planning）把复杂目标拆为可执行子任务：一次性生成整体计划（Plan-and-Execute）、按需逐步规划（ReAct 式边想边做），或用任务树/状态机维护进度。设计要点是给模型提供当前状态、已完成步骤与剩余目标，并限制最大迭代步数防止死循环。

## 工具调用 Function Calling
工具调用（Function Calling）在 Prompt 中声明工具名、功能描述与 JSON 参数 Schema，模型输出结构化的函数名与参数，由应用层真正执行并把结果回填给模型继续推理。关键在于描述清晰、参数类型严格、返回错误信息可读，让模型能自我修正。

## ReAct
ReAct 交替产生 Thought（推理）、Action（调用工具）与 Observation（观察结果），直到给出最终答案。相比纯 CoT，它能把中间结论与真实数据绑定，适合检索、计算、API 调用类任务；需解析动作格式并处理工具失败。

## 记忆
记忆分短期（当前会话的上下文窗口，需摘要压缩防溢出）与长期（向量库存储历史交互、偏好与事实，按相关性召回）；另可用外部文件或数据库作为显式工作记忆。

## Agent 如何安全地调用工具
Agent 如何安全地调用工具，核心是四道防线：
- 工具白名单：只允许注册过的工具，禁止任意 URL、Shell 与代码执行；按场景最小权限授权。
- 参数校验：用 JSON Schema 校验类型与取值范围，白/黑名单过滤路径与域名，服务端二次校验，不信任模型输出。
- 人工确认：对不可逆或高风险操作（删数据、发消息、付款）执行前展示计划并要求人工批准（human-in-the-loop）。
- 审计与隔离：记录每次调用的入参、结果、耗时与调用来源，可回放追溯；沙箱执行、限制步数与重试次数、对工具返回内容视为不可信数据（防间接注入）。
